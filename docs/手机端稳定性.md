# 手机端对战闪退防护

## 结论
手机端只在 3D 对战场景偶发闪退，优先按 Android + GL Compatibility 驱动的已知高风险路径处理，而不是减少单位数量。

## 已调整
- 全局关闭 3D MSAA（`anti_aliasing/quality/msaa_3d=0`）。
- Compatibility 渲染器不支持 screen-space AA，已关闭（`screen_space_aa=0`），避免无效后处理。
- 冲线/普通对战进入时，mobile 分支额外执行：
  - 关闭 **SSAO、Glow、PanoramaSky**（背景改纯色）；
  - 关闭方向光阴影；
  - 3D 渲染分辨率 `scaling_3d_scale=0.72`；
  - 法术不再创建动态 `OmniLight3D`，避免大量动态光源压垮移动 GLES 驱动。
- 桌面端不受影响，仍保留原后处理/阴影，仅 mobile 分支降级。

## 验证
- `tools/mobile_safe_test.tscn`（`CR_MOBILE_SAFE=1` 模拟 mobile）：
  - `[MobileSafe] ssao_off=true glow_off=true shadow_off=true scale=0.72000002861023`
  - `[MobileSafe] PASS=true`
- Android debug APK 已重新导出：`build/ClashRoyale-Net-mobile-safe.apk`

## 如果仍闪退
用 USB 连接手机后执行：

```powershell
adb logcat -b crash -d > crash.txt
adb logcat -d > full.txt
```

保留 `crash.txt` 的 `FATAL EXCEPTION`/`Fatal signal` 与 `libgodot_android.so` 堆栈，才能定位具体驱动/引擎崩溃点。

## 应用内异常退出记录（新增）
- 新增 `CrashLogger` autoload：
  - 启动时创建本次会话，标记 `clean_exit=false`；
  - 每 1 秒把设备、渲染方式、场景、内存/FPS、战斗状态写入 `user://diagnostics/last_session.json`；
  - 原子写入 + `.bak` 备份，避免崩溃瞬间写坏上一份；
  - 战斗每 0.5 秒更新单位/子弹/法术数量、圣水、比分、网络模式，并记录最近出牌/法术事件；
  - 正常退出标记 `clean_exit=true`。
- 下次启动时，若发现上次不是正常退出，主菜单弹窗显示简要诊断，并提供「复制诊断」按钮，可直接粘贴给开发者。
- 历史异常追加到 `user://diagnostics/crash_history.jsonl`。
- 测试：`tools/crash_log_test.tscn` → `previous=true report_ok=true persisted=true`，`PASS=true`。

## APK 签名（解析软件包失败的原因）
- Godot 导出 `--export-debug` 在 `package/signed=false` 时生成的是 **unsigned APK**；Android 安装器会提示「解析软件包时出现问题」。
- 本次已修复：先 `zipalign -p 4`，再用 `apksigner` 签名，v2/v3 验证通过。
- 当前 APK 签名证书为 Godot 本地 debug 证书；如果手机里旧版是用 `tools/release.keystore` 签名的，签名不一致会导致无法覆盖安装：
  - 先卸载旧版再安装；或
  - 提供旧 `release.keystore` 的密码后重签成可覆盖升级的包。
- 以后重新导出后不要直接安装，必须执行：
  ```powershell
  zipalign -f -p 4 app-unsigned.apk app-aligned.apk
  apksigner sign --ks <keystore> --out app-signed.apk app-aligned.apk
  apksigner verify --verbose app-signed.apk
  ```
