# Clash Royale 联机实现方案

## 已确认的范围
- 首版：房间码 1V1，先本地/局域网跑通，再接公网。
- 后续：2V2，首版用共享三塔简化规则。
- 账号：游客 token + 服务端存档。
- 架构：专用权威服务器，不做房主 P2P。

## 总体架构
Android 客户端（Godot）
  │ ENet/UDP：指令可靠，快照不可靠
  ▼
Linux VPS：Godot headless 权威服务器
  ├─ 游客登录 / 服务端存档
  ├─ 房间码 / 匹配
  ├─ BattleSim 权威模拟
  └─ 快照广播 / 重连

客户端只做：拖动卡牌、发送部署请求、渲染服务器快照、显示服务器下发的圣水/手牌/皇冠/表情。
客户端不结算伤害、不决定费用。

## 协议
消息：
- HELLO {token, client_version}
- LOGIN_OK {profile, server_time}
- CREATE_ROOM {mode}
- JOIN_ROOM {code}
- ROOM_STATE {players, ready, mode}
- READY
- START {match_id, seed, slots, arena}
- DEPLOY {seq, card_id, x, z}
- DEPLOY_ACCEPT / DEPLOY_REJECT
- SNAPSHOT {tick, units, bullets, spells, towers, slots, emotes}
- EMOTE {id}
- MATCH_END {winner, crowns}
- RECONNECT {token, match_id}
- PING/PONG

传输：
- ENet 通道 0：登录/房间/部署，可靠；
- 通道 1：快照，不可靠 sequenced；
- 通道 2：表情/聊天，可靠。
- 快照目标 20Hz，客户端插值到 60FPS。
- 快照用紧凑二进制/PackedByteArray，不用 JSON 全量广播。

## 服务器
- Godot headless，Linux 专用服务器导出。
- 单进程 RoomManager + 多个 BattleSim；后续按 CPU 拆进程。
- 固定 tick 20Hz；客户端不模拟战斗。
- 游客 token：首次启动生成 UUID，服务端创建 profile；卡组/等级/金币服务端保存。
- 原型阶段 profile 用 JSON 原子写；正式量级换 SQLite/Postgres。
- 断线保留 slot 30 秒，重连发全量快照。

## 代码改造
1. BattleManager 拆出 PlayerSlot：
   - 每 slot：peer_id、team、deck、hand、elixir、king_tower、owner_slot。
   - Unit.team 仍 0/1；额外 owner_slot 用于统计。
2. 新增 BattleSim（权威模拟）：
   - 可由现有 BattleManager 逻辑逐步抽出；
   - 首版可先复用 BattleManager，加 server_mode 禁 HUD/AI/录像。
3. 抽出 SnapshotBattleView：
   - 从 ReplayUI 的 snapshot 渲染层抽取；
   - 联机对战和录像回放共用。
4. HUD 支持多人：
   - 自己底部手牌/圣水；
   - 顶部队友/对手信息；
   - 2V2 显示 4 人皇冠/连接状态。
5. 新增网络层：
   - NetworkClient.gd：连接、重连、消息队列；
   - NetworkServer.gd：ENet host、房间、会话；
   - RoomManager.gd：房间码、ready、开局；
   - MatchRoom.gd：单局权威循环。
6. 客户端入口：主菜单“联机” → 创建/加入房间 → 准备 → 战斗。

## 2V2 首版规则
- 4 个 player slot：team0 两个、team1 两个。
- 每队共享国王塔 + 双公主塔（三塔）。
- 每个玩家独立手牌、独立圣水；皇冠/胜负按队伍共享。
- 每个玩家只能在自己半场部署；队友可互相配合。
- 队友/对手表情广播。
- 一人掉线：保留 30 秒；超时队友可投降或 AI 接管（后续）。

## VPS 推荐
- 大陆玩家优先：阿里云/腾讯云轻量 2C4G，5Mbps，Ubuntu 24.04，上海/北京。
- 不想备案/面向海外：腾讯云香港/新加坡轻量 2C2G，30Mbps。
- 首版 2C2G 足够小规模；正式按并发升 4C8G。
- 只开 SSH + UDP 游戏端口；ENet 直连 IP 不需要域名/TLS；后续 HTTP 登录再上域名+Caddy。
- 部署：Linux 专用服务器导出 → `/opt/clash/server` → systemd 常驻；日志轮转；健康检查。

## 里程碑
M1 1V1 房间码：网络握手、房间、部署、快照、结算、重连。
M2 服务端存档：游客 token、卡组/等级校验、战绩。
M3 2V2：4 slot、共享三塔、2V2 HUD、4 人重连。
M4 公网运营：VPS、监控、压力测试、反作弊、版本兼容。
