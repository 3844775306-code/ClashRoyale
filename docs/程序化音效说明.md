# 程序化音效（替代官方版权音频）

## 原则

不使用任何 Supercell 官方音效/音乐（版权 + 粉丝内容政策限制），改为**代码合成**：
全部音频由 `scripts/core/ProceduralAudio.gd` 在运行时生成 `AudioStreamWAV`（16-bit / 22050Hz / 单声道），首次调用合成并缓存，后续零开销。生成结果与素材库无关，可商用/分发。

## 提供的音色

| 名称 | 时长 | 用途 | 音色设计 |
|---|---|---|---|
| `arrow` | 0.18s | 远程单位攻击 | 低通噪声 + 1100→400Hz 下滑正弦，短衰减 |
| `victory` | 1.70s | 对局胜利 | C-E-G-C 上行琶音 + 收尾大三和弦 |
| `defeat` | 1.90s | 对局失败 | G-E-D-A 下行小调音，低八度叠音 |
| `menu_theme` | 8.57s | 菜单音乐**兜底**（正常用你自己的 OGG） | 112BPM、C–G–Am–F 四小节；不做引擎级循环，由 `finished` 重播 |

## 菜单音乐：使用你自己的资源（2026-11-18）

- 文件：`assets/audio/bgm/menu_theme.ogg`（来自你的资源 `Documents/assets/UI015-部落冲突：皇室战争/music/menu_03.ogg`，96 秒）
- `assets/ui/MainMenu.gd` 优先加载该 OGG；文件缺失时才回退到程序化 `menu_theme`
- 循环方式：不开启引擎级 loop，`AudioManager.play_bgm` 在 `finished` 后重新 `play()`，
  避开部分 Android 音频后端在循环点上的崩溃（你的闪退正好固定在音乐同一位置，高度怀疑是旧程序化 WAV 的循环点）

## 接入位置

| 文件 | 位置 | 说明 |
|---|---|---|
| `scripts/entities/Unit.gd` | `_attack()` 音效段 | 远程单位（attack_range>1.5）用 `arrow`，近战仍用 `attack_melee.wav` |
| `scripts/core/BattleManager.gd` | `_show_game_over()` | 胜负改用 `victory` / `defeat`（不再借用 BGM 片段） |
| `assets/ui/MainMenu.gd` | `_ready()` | 菜单 BGM 优先用 `assets/audio/bgm/menu_theme.ogg`，缺失则程序化兜底 |

调用方式：

```gdscript
const ProceduralAudio := preload("res://scripts/core/ProceduralAudio.gd")
var stream: AudioStream = ProceduralAudio.get_sound("arrow")
AudioManager.play_sfx(stream, global_position)
```

> 没有使用 `class_name`，避免全局类缓存未刷新时 "Identifier not declared" 的问题。

## 试听 / 校验

`tools/audio_check.gd` 会生成全部音色、打印时长/峰值/RMS/生成耗时，并导出 wav 到 `docs/audio_samples/`（`arrow.wav`、`victory.wav`、`defeat.wav`、`menu_theme.wav`）：

```bash
godot --headless --path . --script res://tools/audio_check.gd
```

实测生成耗时（桌面）：arrow 1ms、victory 25ms、defeat 27ms、menu_theme 90ms；峰值统一归一化到 0.95，无削波。战斗浸泡 20s：0 条 ERROR。

## 调整方法

都集中在 `ProceduralAudio.gd`：

- 采样率：改 `const SR`
- 箭矢音：`_arrow_samples()` 里的扫频范围/噪声低通系数
- 胜负音：`_victory_samples()` / `_defeat_samples()` 的音符数组（频率 Hz）
- 菜单音乐：`_menu_theme_samples()` 的 `bpm`、`chords`（和弦频率）、`arp`（琶音型）、`bass`（低音）
- 音量/归一化：`_wav()` 里的 `gain`（0.95 为峰值上限）

## 说明

`docs/audio_samples/*.wav` 只是试听副本，不参与游戏运行（运行时直接用内存合成流），不需要时可直接删除。

## 播放架构：常驻播放器池（2026-11-17 修复手机闪退用）

第一版 `AudioManager.play_sfx` 是"每次播放 new 一个 AudioStreamPlayer(3D)，播完 queue_free"。这套写法在桌面没问题，但手机端战斗激烈时（尤其远程单位攻击音效从"缺失静音"变成"真的会响"之后）每秒会创建/销毁几十个播放器与 `AudioStreamPlayback`，而 Godot 音频混音线程存在"释放后仍被读取"的竞态风险（社区同类问题：godotengine/godot#124217），高频率释放 playback 更容易触发原生崩溃。

现在改为：

- 每个音效流只创建一个**常驻**播放器（`_players3d` / `_players2d` 字典，最多 `MAX_VOICES = 10` 个），挂在 `AudioManager` 下
- 再次播放时 `stop() → play()`，**复用同一个 AudioStreamPlayback**，不重建、不 `queue_free`、不连接 `finished`
- 同一音效最小间隔 `Config.SFX_MIN_INTERVAL_MS`（默认 35ms），避免同帧刷爆声部
- 超出上限才淘汰最旧的一个（正常音效种类 < 10，几乎不会走到）

## 排查开关（A/B 测试用）

`scripts/core/Config.gd`：

```gdscript
const SFX_ENABLED: bool = true          # 改 false：BGM + 全部音效静音
const SFX_MIN_INTERVAL_MS: int = 35     # 同音效最小间隔
```

如果手机版仍闪退，先导一个 `SFX_ENABLED = false` 的静音包对比：
- 静音包不闪退 → 基本锁定音频方向，再试切换 Android 音频驱动（AAudio → OpenSLES）或降低声部；
- 静音包仍闪退 → 偏 GL/渲染或内存方向，抓 logcat 看 `AAudio/AudioFlinger/Fatal signal` 还是 `libGLES/Adreno/Mali`。
