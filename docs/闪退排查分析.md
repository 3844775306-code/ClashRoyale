# 手机版（Android）对战一段时间后闪退：排查分析

生成时间：2026-11-17 01:35（本地）
排查对象：Godot 4.7.2 + gl_compatibility 导出 Android；"开局对战一段时间后闪退"

## 一、已做的验证（本机可复现的部分）

| 验证 | 方法 | 结果 |
|---|---|---|
| 桌面 headless 浸泡 50s | `tools/soak/soak_test.tscn` 自动双方下牌，场上 47-75 单位 | 内存 182-196MB、节点 1930-2170、对象 7000-8400，**无增长趋势**；无崩溃 |
| Windows GL Compatibility 实渲染 45s | 同上，`--rendering-method gl_compatibility --rendering-driver opengl3` | 内存 153-157MB、节点 1300-1470，**无 GL/Shader/instance uniform 报错**；无崩溃 |
| 导出 Android PCK 战斗 15s | `--export-pack` 后用 `--main-pack` 跑战斗 | `data/units_level11_utf8.csv` **已正确打包，129 条加载正常**；无资源缺失（除音频）；无崩溃 |
| 退出泄漏 | PCK 运行退出 | 15 个 ObjectDB 实例 / 4 个 resource 泄漏（少量，非主因） |

结论：**桌面与导出 PCK 均未能复现闪退，也没有发现明显的内存/节点泄漏**。因此 Android 闪退要么是手机端专属（GLES 驱动、音频、系统内存/ANR），要么由下面这些"战斗期持续异常"在手机端放大导致。真正的结论需要手机 logcat（见第五节）。

## 二、战斗期持续异常（已量化，手机端会被放大）

浸泡 50 秒（游戏内时间）产生 **11,031 条 ERROR（≈220 条/秒）**，GL 实渲染 45 秒 5,154 条（≈115 条/秒）：

| 次数/50s | 错误 | 来源 |
|---|---|---|
| 6,574 | `Condition "!is_inside_tree()" ... get_global_transform()` | 单位/子弹在 `add_child` 之前就设置 `global_position` |
| 3,657 | `Resource file not found: res://assets/audio/sfx/arrow.ogg` | 远程攻击音效路径写错（实际只有 `arrow.wav`） |
| 432 | `look_at_from_position ... not inside tree` | 同上，入树前设置朝向 |
| 366 | `Node not found: "CollisionShape3D"` | `die()` 里取已被移除的碰撞体 |
| 1 | `defeat.ogg` / `menu_theme.ogg` / `victory.ogg` 缺失 | 结算/菜单音效路径不存在 |

每条错误都会在主线程分配字符串并写 stdout/logcat。手机端 logcat 写入更慢，100-200 条/秒的日志洪水会造成明显卡顿、GC 压力，严重时触发 ANR 被系统杀掉（表现就是"玩一会儿闪退"）。

## 三、已定位的问题（按建议修复优先级）

### P0（建议立刻修，低风险）
1. **`global_position` 在入树前设置**
   - `scripts/core/BattleManager.gd:715/723/727`（设 `unit.global_position`）在 `:729` `units.add_child(unit)` **之前**
   - `scripts/entities/Unit.gd:1215`（`bullet.global_position`）在 `:1234` `battle.bullets.add_child(bullet)` **之前**
   - `scripts/entities/Spell.gd:31` 同类问题
   - 修复：先 `add_child` 再设 `global_position`（或设 `position`）。可消除 6,500+ 条/50s 错误。
2. **音效路径不存在**
   - `Unit.gd:1086` `arrow.ogg` → 改为 `arrow.wav`（已有）
   - `BattleManager.gd:1229/1233` `victory.ogg` / `defeat.ogg` → 用 `assets/audio/bgm/scroll_win_02.ogg` / `scroll_lose_01.ogg`
   - `assets/ui/MainMenu.gd:6` `menu_theme.ogg` 不存在 → 改用已存在 BGM 或补文件
   - 可消除 3,600+ 条/50s 错误。
3. **`die()` 取已移除的 CollisionShape3D**（`Unit.gd:1372`）
   - 改为 `var col := get_node_or_null("CollisionShape3D")` 并判空（同文件 1166/1321 行已有正确写法）。

### P1（稳定性相关）
4. **音效播放无上限**：`AudioManager.play_sfx` 每次 new 一个 `AudioStreamPlayer(3D)`，`await finished` 后释放；实测战斗中并发 30-56 个声源。手机端建议：
   - 池化播放器（8-12 个）、同帧同音效去重、按距离/音量丢弃远处音效；
   - 加 `if stream == null: return`，避免空流；
   - 场景销毁时 `finished` 永不触发会导致协程挂起（多次对局累积）。
5. **每个受击/特效都新建网格与材质**（`Unit.gd:1247-1260` 受击火花、`BattleManager._spawn_effect`、圣水特效等）。手机端 CPU/内存抖动大，建议共享缓存的 `SphereMesh` / `StandardMaterial3D`。

### P2（Android 渲染相关，需实验确认）
6. `scenes/battle.tscn` 的 Environment：`ssao_enabled = true`（**Compatibility 渲染器不支持**）、`glow_enabled = true`、`project.godot` 的 `anti_aliasing/quality/screen_space_aa=1`（启动已警告不支持）、`msaa_3d=1`。
   - 手机端建议先关 SSAO / Glow / FXAA（保留 MSAA 或改 0）做对比；部分 Mali/Adreno 驱动在 Glow + 后处理组合下会崩。
7. `toon_unit.gdshader` 使用 7 个 `instance uniform`（u_flash/u_freeze/...）。桌面 GL 3.3 实测正常，但个别 Android GLES3 驱动对 instance uniform 支持不完整，可作为对比实验项（临时改成顶点色或材质参数切换验证）。

### P3（数据/清理）
8. `BattleManager.gd:1418` 依次尝试 `units_level11.csv`（GBK）→ `units_level11_utf8.csv`；GBK 文件每次开局都会触发 Unicode 解析错误后再回退。建议改成优先 utf8，或删掉 GBK 文件。
9. `_run_miner_tunnel` / `_deploy_log_like` 等新增逻辑里有 `await` 后访问单位/节点的代码，缺少 `is_instance_valid` 保护；单位在协程期间死亡会报错（不是崩溃主因，但会加日志）。

## 五、定位手机真因（需要连一次手机，5 分钟）

1. 导出 **Debug** 包（编辑器：项目 → 导出 → Android → 勾选 Debug；或 `godot --headless --export-debug Android`）。
2. 手机开 USB 调试，`adb devices` 能看到设备；`adb logcat -c` 清空日志。
3. 启动游戏，打到闪退，立即：
   ```bash
   adb logcat -d > crash.txt
   ```
4. 在 crash.txt 里搜这些关键字判断类型：
   - `Fatal signal` / `SIGSEGV` + `libGLES` / `Adreno` / `Mali` → **GL 驱动崩溃**（先关 SSAO/Glow/FXAA/MSAA 验证）
   - `AndroidRuntime` / `FATAL EXCEPTION` → Java 层（LootLocker 插件、权限）
   - `lowmemorykiller` / `Out of memory` / `dvm` → 内存（配合游戏内内存监控）
   - `audio` / `AudioFlinger` / `AAudio` → 音频（先做 P1 音效池化）

> 本机 `adb` 存在但当前没有连接设备，所以无法直接给出 logcat 结论。

## 八、音频方向复查与修复（2026-11-17，用户反馈"手机版非常容易闪退，疑似合成音效"）

### 复查发现的放大链条
1. 修复前远程攻击音效指向不存在的 `arrow.ogg` → `load` 返回 null → **静音且不产生播放器**。
2. 接入程序化音效后，远程单位每次攻击都会创建 `AudioStreamPlayer3D` 并 `play()`；
   同时命中音效 `hit.wav` 本来就在每次受伤时创建播放器。
3. 第一版实现是"播放时 new 节点，`finished` 后 `queue_free`"。激烈交战时每秒会产生
   几十次 **AudioStreamPlayer(3D) + AudioStreamPlayback 的创建/释放**。
4. Godot 4 的音频混音线程存在"释放后仍被读取"的竞态类问题
   （社区同类 issue：[godotengine/godot#124217](https://github.com/godotengine/godot/issues/124217)），
   高频率释放 playback 会显著提高触发概率 → 手机端闪现 native 崩溃（logcat 里通常是
   `Fatal signal` + `libaudioclient/libaaudio/AudioFlinger` 栈）。
5. 桌面 Windows 音频驱动/线程调度不同，所以桌面浸泡看不出来，符合"只有手机容易崩"的表现。

### 已做的修复（`scripts/core/AudioManager.gd` 重写）
- 每个音效流只创建一个**常驻播放器**，最多 10 个；重复播放用 `stop() → play()`，复用 playback，
  **战斗中不再创建/销毁音频节点**，也不再连接 `finished` 或 `queue_free`。
- 同一音效 35ms 节流（`Config.SFX_MIN_INTERVAL_MS`），避免同帧爆声部。
- 新增 `Config.SFX_ENABLED` 开关，可一键出"静音包"做 A/B 排查。

### 验证结果（桌面 headless 30s 自动对战）
| 指标 | 修复前（旧播放器方案） | 修复后（常驻池） |
|---|---|---|
| 音频节点数 | 峰值 25-61，随战斗波动 | **恒定 6-10（不增长）** |
| 引擎 ERROR | 0 | 0 |
| 内存 | 170-188MB | 175-187MB（稳定） |

### 手机上如何确认
1. 先导出当前版本打一局；仍闪退则导一个 `Config.SFX_ENABLED = false` 的静音包对比：
   - 静音包**不闪退** → 音频方向坐实，接着试 Android 音频驱动（AAudio→OpenSLES）与更低声部；
   - 静音包**仍闪退** → 回到渲染/内存方向，抓 logcat 区分：
     - 音频：`AAudio`、`AudioFlinger`、`AudioTrack`、`Fatal signal` 栈含 `libaudioclient/libaaudio`
     - 渲染：`libGLES`、`Adreno`、`Mali`、`EGL`
2. 抓取命令：`adb logcat -c` → 复现 → `adb logcat -d > crash.txt`，搜 `Fatal signal` 前后 50 行。

## 九、主菜单音乐导致闪退（2026-11-18，按用户观察修复）

### 现象与判断
用户观察：**每次闪退都发生在主菜单音乐播放到同一位置**。此前菜单音乐是程序化生成的
8.57 秒 `AudioStreamWAV`，并设置了 `LOOP_FORWARD`（`loop_end = 样本数`）。崩溃固定在
"同一位置"高度符合**循环点**问题：部分 Android 音频后端（AAudio/OpenSLES）在 WAV 循环回绕处
容易出现越界读取/竞态，而桌面音频驱动不会复现——这与"只有手机、且总在同一时刻闪退"一致。

### 修复
1. **改用用户自己的主菜单音乐**：`Documents/assets/UI015-部落冲突：皇室战争/music/menu_03.ogg`
   （96 秒）复制为 `assets/audio/bgm/menu_theme.ogg`，`MainMenu._ready()` 优先加载它；
   程序化 `menu_theme` 仅在文件缺失时兜底。
2. **去掉引擎级循环**：`play_bgm` 不再依赖 stream 的 loop 设置，改为 `finished` 后重新 `play()`
   （OGG 播完 96s 再重播）；程序化兜底也改为非循环 WAV，同样由 `finished` 重播。
   这样彻底绕开 WAV/OGG 在音频后端上的循环点回绕路径。
3. 播放器仍为常驻（`bgm_player` 单例），菜单切换/战斗切换不会重建音频节点。

### 验证
- `tools/check_menu_music.gd`：`menu_theme.ogg` 加载成功（`AudioStreamOggVorbis`，96.0s，`loop=false`）
- 启动主菜单 6 秒：无音频相关错误（仅剩已知的 `FXAA 不支持` 警告与 GameManager 启动期
  "Parent node is busy" 既有报错）
- 战斗浸泡 30s：0 条 ERROR，音频节点数恒定

### 手机上验证
重新导出后停在主菜单超过 2 分钟（跨过原来闪退的时间点），再进一局对战。
- 不再闪退 → 循环点问题坐实；
- 仍在同一位置闪退 → 把 `Config.SFX_ENABLED` 设 `false` 出静音包，并按第五节抓 logcat。
