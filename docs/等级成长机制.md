# 等级成长机制（2026-11-16 调整）

## 规则

卡表（`BattleManager.load_card_configs()`）中的生命/伤害等数值视为 **11 级**（当前锦标赛标准）基准值，最高等级 **16 级**。

```
value(level) = base × 1.10^(level - 11)
```

- 11 级 = 基准（不变）
- 每升 1 级 +10%
- 1 级 = 基准 × 0.386，16 级 = 基准 × 1.611
- 等级范围 1-16（`Config.LEVEL_MAX = 16`）

实现位置：`scripts/core/Config.gd`

```gdscript
const LEVEL_BASE: int = 11
const LEVEL_GROWTH: float = 1.10
const LEVEL_MIN: int = 1
const LEVEL_MAX: int = 16

func level_mult(level: int) -> float:
	return pow(LEVEL_GROWTH, float(clampi(level, LEVEL_MIN, LEVEL_MAX) - LEVEL_BASE))

func battle_level(level: int) -> int:
	if TEST_MODE:
		return TEST_LEVEL
	return clampi(level, LEVEL_MIN, LEVEL_MAX)
```

## 测试模式（`Config.TEST_MODE = true`）

- 战斗中**所有卡牌 / 塔统一按 11 级（`Config.TEST_LEVEL`）结算**，与存档等级、升级界面无关
- 覆盖点：`Unit.gd` 单位初始化（含双方卡牌、召唤物、塔），`BattleManager.gd` 4 处法术伤害结算
- 关闭测试模式：把 `Config.TEST_MODE` 改为 `false`，即按真实等级结算

## 与官方逐级表的一致性

以骑士（11 级基准 1766 血 / 202 伤）为例，新公式与 scbase.cn 官方数据对比：

| 等级 | 新公式生命 | scbase 官方生命 | 差 |
|---|---|---|---|
| 1 | 681 | 681 | 0 |
| 9 | 1460 | 1460 | 0 |
| 11 | 1766 | 1766 | 0 |
| 12 | 1942 | 1943 | -1（int 截断） |
| 15 | 2585 | 2586 | -1（int 截断） |
| 16 | 2844 | 2844 | 0 |

即：**该机制与官方“11 级基准 + 每级 ×1.1、上限 16 级”完全对齐**（仅整数截断带来 ≤1 的误差）。

## 等级上限改动点

| 位置 | 改动 |
|---|---|
| `scripts/core/Config.gd` | `LEVEL_MAX = 16`（`level_mult` 同步钳制到 16） |
| `scripts/data/PlayerData.gd` | 卡牌升级上限、塔等级上限、AI 等级、经验上限判断均改用 `Config.LEVEL_MAX` |
| `scripts/ui/CardUpgradeUI.gd` | `MAX_LEVEL = 16` |
| `assets/ui/MainMenu.gd` | 塔等级 MAX 显示判断改用 `Config.LEVEL_MAX` |

## 影响提示

- 同一“显示等级”下，新数值 = 旧数值 × `1.1^(L-11) / 1.05^(L-1)`：1 级 ≈ 0.386×、11 级 ≈ 0.614×、15 级 ≈ 0.740×
- 升级收益从每级 +5% 提升到 **+10%**；11 级→16 级总成长 1.61×，1 级→16 级总成长 4.18×
- 当前开启测试模式，所有对局按 11 级结算（即卡表原值），无需先刷等级
