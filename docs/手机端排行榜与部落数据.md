# 手机端排行榜 / 部落数据无法获取（排查与修复）

时间：2026-11-18

## 现象

桌面（编辑器/PC）排行榜和部落正常，Android APK 打开后排行榜为空、部落列表加载失败。

## 根因

排行榜和部落都走 **LootLocker SDK**。SDK 启动时从 `res://LootLockerSettings.cfg`
读取 `api_key` / `domain_key`（见 `addons/LootLockerSDK/Game/Internals/LootLockerInternal_Settings.gd:26,62`）。

实测你手机安装的包 `ClashRoyale-AI-v5.apk`（2026-11-17 23:45）是 **assets 目录式导出**，
里面**没有** `assets/LootLockerSettings.cfg`（只有 `.godot/global_script_class_cache.cfg`）：

| 文件 | 在 APK 内 |
|---|---|
| `LootLockerSettings.cfg` | ❌ 缺失 |
| `data/units_level11_utf8.csv`（运行期要读） | ❌ 缺失（只有 .translation/.import） |
| `data/trophy_road_rewards.json` | ✅ 有 |
| `addons/...gdc` 脚本 | ✅ 有 |

于是手机上 `LootLockerSettings` 的 apiKey/domainKey 为空 → `GuestSession` 登录失败 →
`LeaderboardAPI.get_leaderboard()` 返回空、`ClanManager` 的所有 `LL_Leaderboards` 请求失败。
PC 上因为工程目录里有这个 cfg，所以一切正常。

桌面端直连 LootLocker 的验证（`tools/test_lootlocker.gd`）：

```
api_key_len=36 domain=z59zdqpt url=https://z59zdqpt.api.lootlocker.com
login success=true
leaderboard success=true  items=1
clan_list success=true  items=3
```

说明服务端/排行榜 key 都正常，问题只在"导出包没带配置"。

## 修复

1. **导出预设加 include_filter**（`export_presets.cfg` 的 Android / Windows / Web / iOS 四个预设）：
   ```
   include_filter="LootLockerSettings.cfg, data/units_level11_utf8.csv, data/trophy_road_rewards.json"
   ```
   实测重新导出后 PCK 中 `res://LootLockerSettings.cfg` 存在且可读。
2. **代码兜底**（`scripts/core/LeaderboardAPI.gd`）：启动时若检测到 LootLocker 配置为空，
   用内置的 api_key/domain_key 补齐单例并打印警告，保证即使导出配置又漏了也能登录：
   ```gdscript
   func _ready():
       _ensure_lootlocker_settings()
       await authenticate()
   ```
   已模拟"cfg 不存在"验证：兜底后 login success、排行榜/部落列表均能拉到。
3. 需要**重新导出 APK** 才生效（旧的 `ClashRoyale-AI-v5.apk` 仍然是坏的）。

## 验证方法

```bash
# 桌面：确认 LootLocker 可用（应输出 login/leaderboard/clan_list success=true）
godot --headless --path . --script res://tools/test_lootlocker.gd
```

手机端装新包后：
- 打开排行榜应显示数据；`adb logcat | findstr /i "LootLocker Leaderboard ClanManager"` 可看到
  `[LootLocker] 登录成功` 与 `[Leaderboard] 获取成功, 共 N 条`；
- 若显示"加载失败：xxx"，把 xxx 或 logcat 发给开发者即可继续定位。

## 附带发现（未修，建议后续处理）

`data/units_level11_utf8.csv` 是 **CSV 翻译导入的源文件**，Godot 导出时只带
`.translation`/`.import`，不带源 `.csv`（实测 PCK 里 `data/units_level11_utf8.csv` 不存在）。
所以手机端 `BattleManager._try_load_unit_table()` 找不到 CSV，会**回退到硬编码卡表**
（约 120 条，缺少 119-129 的新卡数据），导致手机与 PC 的卡牌数值/卡池不一致。
（`trophy_road_rewards.json` 是普通 JSON，正常打进包了。）

可选的修复方向（需要确认，改动不大）：
- A. 运行期优先读一个非导入的副本 `data/units_level11_utf8.csv.txt`（复制 CSV 内容，导出时随包），
  启动脚本或导出前跑一次同步；
- B. 把 CSV 转成 `.tres`/`.res` 资源（Godot 会自动导出），CSV 仍作为编辑源，导出前重新生成；
- C. 直接把 CSV 内容生成进 GDScript 常量作为手机端兜底（体积 +20KB，零文件依赖）。
